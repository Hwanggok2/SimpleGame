# 4차 작업 계획 — 모바일 조준 조이스틱

## 1. 목표

좌측 조이스틱으로 이동 목적지의 방향과 거리를 미리 조준하고, 우측 공격 버튼으로만 해당 목적지의 이동·공격 명령을 확정한다. 기존 월드 직접 터치 조작은 그대로 유지한다.

## 2. 확정 입력 규칙

1. 좌측 360도 `AimJoystickControl`을 누르거나 움직여도 진행 중인 이동·공격 명령에는 개입하지 않고 조준 상태와 가이드만 시작한다.
2. 조이스틱 드래그는 `PlayerController`의 조준 입력과 가이드만 변경한다. 드래그 자체로는 이동하거나 공격하지 않는다.
3. 패드 중심부터 가장자리까지의 입력 크기 `0..1`을 레이 길이에 선형으로 대응시킨다.
4. 최대 입력의 레이 끝점은 현재 카메라 Viewport에서 해당 방향의 가장자리보다 월드 좌표 0.5만큼 안쪽이다.
5. 조준 중에는 Player에서 끝점까지 하늘색 월드 공간 레이와 마름모 끝점 이펙트를 표시한다.
6. 우측 `AttackCommandButton`은 클릭 완료가 아니라 Pointer Down 시점에 현재 끝점의 스냅샷을 확정한다. 확정 위치는 기존 `PlayerController.TryIssueCommand` 경로로 전달해 기존 직접 터치와 같은 이동·타깃 선택·공격 규칙을 사용한다.
7. 공격 버튼이나 월드 직접 터치는 현재 조이스틱 입력과 가이드 끝점을 초기화하지 않는다. 공격 명령 후 조이스틱을 더 움직이면 다음 명령의 끝점만 바뀌며 이미 발행된 명령은 이전 스냅샷을 유지한다.
8. 조이스틱에서 손을 떼면 입력과 끝점을 현재 Player 위치로 되돌리고 가이드를 숨긴다. 이 동작만으로 이미 발행된 이동·공격 명령을 취소하지 않는다.
9. 입력 크기가 `0.01` 미만인 중립·근중립 상태에서는 공격 버튼을 눌러도 명령을 발행하지 않는다.
10. 조이스틱은 처음 누른 `pointerId` 하나만 소유한다. 다른 손가락의 드래그·해제는 무시하므로 한 손은 조준을 유지하고 다른 손은 공격 버튼을 누를 수 있다.

## 3. HUD와 연출

기준 해상도는 세로형 `1080×1920`이다.

| 요소 | 기준 위치 | 크기 | 표현 |
|---|---:|---:|---|
| 좌측 조준 패드 | 좌하단 기준 `(178, 315)` | `280×280` | 원형 터치 영역, `104×104` 하늘색 Knob |
| 우측 공격 버튼 | 우하단 기준 `(-168, 315)` | `224×224` | 원형 붉은 버튼, `공격` 라벨 |
| 조준 레이 | Player 기준 월드 공간 | 폭 `0.08` | 하늘색 반투명 선 |
| 조준 끝점 | 레이 끝 월드 좌표 | `0.42×0.42` | 45도 회전한 하늘색 마름모, 미세 Pulse |

## 4. 구성 책임

| 파일·컴포넌트 | 책임 |
|---|---|
| `AimJoystickControl` | Pointer 소유권, 패드 좌표 정규화, Knob 이동, 조준 시작·갱신·해제 |
| `AttackCommandButton` | Pointer Down 한 번당 공격 Callback 한 번 전달 |
| `PrototypeHUDView` | 조이스틱·공격 버튼 참조 보관, Player 연결, 기존 HUD 버튼 바인딩 |
| `PrototypeHUDPresenter` | 공격 버튼을 `PlayerRoot.ExecuteAimedCommand`에 연결 |
| `PlayerController` | 기존 명령과 독립된 조준 상태 유지, Viewport 기반 끝점 계산, 가이드 갱신, 끝점 스냅샷을 `TryIssueCommand`에 재사용 |
| `PrototypeSceneBuilder` | `1080×1920` HUD의 좌·우 조작 UI 생성 및 View 참조 연결 |
| `CharacterAssetBuilder` | Player Prefab에 월드 공간 `AimRay`·`AimEndpoint` 생성 및 Controller 연결 |

## 5. 수용 테스트

- 조이스틱 중심·절반·가장자리 입력이 각각 레이 길이 `0%·50%·100%`에 대응하고 원 밖 입력은 `100%`로 제한된다.
- 조준 시작·드래그·해제는 진행 중 명령을 취소하거나 새 이동·공격을 발생시키지 않는다.
- 최대 입력의 끝점이 가로·세로·대각선 방향 모두 현재 Viewport 가장자리에서 0.5 월드 단위 안쪽에 위치한다.
- 하늘색 레이와 마름모 끝점이 조준 중에만 보이며 조이스틱 해제 시 Player 위치로 복귀한 뒤 숨는다.
- 공격 버튼 Pointer Down 시점의 끝점으로 명령이 한 번 발행되고, 이후 조이스틱 이동은 그 명령의 목적지를 바꾸지 않는다.
- 공격 명령 직후 조이스틱을 놓아도 발행된 이동·공격 명령은 계속 수행된다.
- 공격 버튼 또는 월드 직접 터치를 사용해도 조준 입력과 표시 끝점은 유지된다.
- 입력 크기 `0.01` 미만에서는 공격 버튼이 명령을 만들지 않는다.
- 서로 다른 두 `pointerId`로 조준 드래그와 공격을 동시에 수행할 수 있고, 두 번째 손가락이 조이스틱 상태를 해제하지 않는다.
- 기존 월드 직접 터치의 이동·Enemy 보정·경로상 Enemy 가로채기 동작이 이전과 동일하다.
- 생성된 Player Prefab과 `PrototypeHUD`에 필수 가이드 Renderer, 조이스틱, 공격 버튼 및 View 참조가 모두 저장된다.
